# Fable 5.1 デザイン能力の検証 [2026-09-02]

## 目的

Fable 5.1 のデザイン能力を、既存デザインに引っ張られない条件で測る。

## 方法

- **渡したもの（要件のみ）**: `BRIEF.md`（事業・ターゲット・旗・制約・出力仕様）／`CONTENT.md`（全12セクションの構成と原稿。背景ラベル・図解の型指定などデザイン判断は機械的に除去）／ロゴSVG実データ
- **渡していないもの**: `docs/DESIGN.md` 全体（配色パレット・参考サイト symdirect・写真を使わない方針・ゴースト文字・矢羽モチーフ・フォント指定）／`design/` 配下の全HTMLとスクショ
- リポジトリ外の隔離ディレクトリで作業させ、「アートディレクションは全てあなたが決めてください。トンマナ指定は意図的に渡していません」と明示
- 同一条件で2案（A/B）を独立に生成。Opus（オーケストレーター）はデザインに一切関与していない
- 追加で **C案**: A/Bと同じブリーフ＋**参考サイト（symdirect）のスクショのみ**を渡した条件。「取る／取らない」の判断（DESIGN.md §4 の我々の結論）は渡さず、Fable自身に解かせた。A/BのHTMLは読まないよう明示

### 検証時の注意

B案は生成完了後も自己修正を続けており、途中版ではヒーロー見出しに段落ちがあった。**最終版では解消**（見出しの行数を実測して確認）。ここに保存してあるのは最終版。

### 注目点

- **既存デザインを一切見せていないのに、A・B両案とも §01 を「課題・顧客・事業＋中央に伝える軸」の三角図で解いた。** 現行 v8 の図解とほぼ同じ構造に独立到達している（原稿の論理構造が強く、図解の解が収束しやすいと解釈できる）
- 両案とも**明朝体を主見出しに選定**。「考える会社」の訴求から書体を導いており、性能軸で差別化しない方針とも整合
- A案は「考える＝明朝／つくる＝モノスペース」という書体の役割分担で旗（考える人とつくる人を分けない）を紙面構成として体現させたと説明している
- 顔写真なしの制約に対し、A案はロゴシンボルの3本ストロークをモチーフ化して代替

## C案：参考サイトの消化力

Fable自身の説明による判断。

**取り入れた**
1. セクションごとの全面色面切り替え（参考の紫・墨・クリーム・ミント → RE DESIGNの赤・墨・生成りに翻訳）
2. 斜めシェブロンのモチーフ（ただし参考の紫の斜線ではなく、**自社ロゴのシンボルから派生**させブランド固有の形に）
3. 左上の小さな英字ラベル＋罫線、大きな番号、ピル型タグ（情報の秩序をつくる汎用パターン）

**取り入れなかった**
4. 巨大な英文ワードマーク見出し（"Problem Definition" 等）— 相場を知らない中小事業者がターゲットのため、和文の主張見出しを主役にし英字は小ラベルに留めた
5. 写真主体のレイアウト — 実写素材も顔写真も使えないため、写真枠をすべて図解（三角図・ファネル・体制図・ワイヤーフレーム）に置換

**評価**: なぞりではなく翻訳になっている。特に「参考の斜線モチーフを自社ロゴのシェブロンに置き換える」「素材がない制約を図解で埋める」は、我々がDESIGN.mdで到達した結論と実質同じ判断に独立到達した。
