# 03 Process — 全幅パターン P1 / P2 / P3 [2026-09-05]

対象: `03-p1.html` / `03-p2.html` / `03-p3.html`（各1440px幅・単体で開ける）。
スクショ: `shot-03-p{1,2,3}.png`（1440px、Playwright / Chromium、段階スクロールでリビール発火後）。

## この3案の前提

却下された6案（`proposals/03-{a,b,c}.html`・`proposals/split/03-{a,b,c}.html`）の
「どれもわかりづらい」の原因＝**Before/After の対比を幅580px前後の狭い右カラムに押し込んで密度が上がっていた**
（`docs/DESIGN.md` §25）。

今回の共通の変更点は1つだけ:
- **左右2カラム（左に見出し・右に図）を外し、全幅で図を組んだ**
- 却下案で使った表現（同心円の循環図・スクロール連続変化）は使っていない
- 原稿は一字も変えていない。h2 の「分けない」だけをアクセント赤
- 工程名・担当名は18px以上、キャプションは15px以上（01 の「文字が小さい」指摘への対応）

## P1「左右2分割の対比」

- **狙い**: 中央の縦の仕切りで画面を左右に割り、左半分＝Before、右半分＝After。
  **4工程を同じ高さに揃えて並べ**、担当だけが違うことを一目で見せる。
  Before は担当A〜Dが工程ごとに変わり、あいだに「伝達」の矢印が入る。After は赤い1枚の板（設計責任者）が4工程すべてに接続する
- **却下案の何を直したか**: 図を1つの狭いカラムに縦積みしていたのをやめ、**Before と After を横並びの同スケールで置いた**。
  対比は「隣に並べる」のが一番わかりやすい、という一番素直な解
- **判断**: 巨大英字 `Process` は残した（h2 が2行で左半分に収まるため競合しない）
- **リスク**: 縦に長い（1010px）。1440px 未満では左右分割が窮屈になる
- **実装コスト: 低**（左右対称の2ブロック。モバイルは Before → After の縦積みにそのまま落ちる）

## P2「横に流れる2本の帯」

- **狙い**: **工程名を1組だけ中央に置き**、その上に Before の帯（4つに切れた黒）、下に After の帯（1本の赤）。
  比較対象を「担当の連続性」だけに絞り、工程は1回しか書かない＝読む量が半分になる
- **却下案の何を直したか**: Before と After で工程名を2回書いていたのをやめ、**共通項を1組に統合**した。
  「切れている / つながっている」という形の差だけが情報になる
- **判断**: 巨大英字 `Process` は残した
- **修正**: 赤い帯の白ドットが「設計責任者」ラベルと重なっていたため、1つ目のドットを外した（ラベル自体が工程01の位置に載る）
- **リスク**: 左に説明ラベル・右に帯という配置になり、見出しは全幅でも図は左右に分かれて見える。
  02（左固定×右縦積み）の直後に来るとリズムが似る
- **実装コスト: 中**（横長の帯。モバイルでは Before / 工程 / After の3行を縦向きに組み替える必要がある）

## P3「見出しと図を重ねる」

- **狙い**: h2 を **60px・全幅1行**で大きく置き、その真下を **赤い線が左から右へ4工程を貫く**。
  「考える人と、つくる人を分けない。」という文と、線が切れずに通っている図が、同じ1つのブロックとして読める。
  Before は同じ4工程の直下に「切れた薄い線＋担当A〜D」として**影のように**添える
- **却下案の何を直したか**: Before と After を対等に扱うのをやめ、**After を主役・Before を副えものにして情報量そのものを減らした**。
  リードは図の下に3列で流し、図の読解を邪魔しない位置に移した
- **判断**: 巨大英字 `Process` は**外した**（60px の h2 と重なって競合するため）
- **修正**: 担当D と工程04 が右端からはみ出していたため、工程の中心x を 350/624/898/1172 → 340/606/872/1138 に寄せ、
  絶対配置のラベルに `white-space:nowrap` を追加した
- **リスク**: h2 が `white-space:nowrap` の1行なので、1440px 未満では級数を落とす前提が要る。
  リードが図の下＝画面下部に来るので、読み順が「結論→根拠」になる（01・02 とは逆）
- **実装コスト: 中**（座標系は素直だが、h2 と図の幅を連動させる必要がある。モバイルは h2 を2行に折り、線を縦にする）
