## 前提: 主題を変えた

P1〜P6（および却下6案）はすべて主題が「担当の並び方の比較」（担当A〜D vs 設計責任者＝組織図）だった。
組織図は **症状（人が入れ替わる）** しか描けず、**原因（理由が引き継がれない）** が描けていなかった。

P7 の主題は
**「成果物は引き継げます。でも『なぜそうしたのか』は引き継げません。」**
図は組織図ではなく、**4工程を横に並べ、その上を通る2本の線**。担当A〜D・人のアイコン・ピル・体制ラベル（一貫／一括／一人で／自社）は一切出していない。

## 何を狙ったか

- **「他社は仕事をしていない」と読まれないこと。** 上の線＝成果物は Before でも After でも切れずに通す。
  違いは下の線＝「なぜそうしたのか」だけ。Before/After で 成果物の線・マーカー・工程・ラベルは **1pxも変えていない** ので、
  目で見比べたとき残る差分が「下の線が切れているか、1本か」の1点に絞られる
- **原因を描く。** Before の「なぜ」の線は、工程の切れ目（担当が変わる位置）で途切れ、区間ごとに 100% → 58% → 34% → 18% と薄れる。
  本文2「最初に決めた『誰に、何を伝えるか』だけが少しずつ薄れていく」をそのまま図にしている。
  切れ目の位置には工程行から縦の破線を落とし、Before と After を貫かせた。成果物の線はこの破線を横切って通り、「なぜ」の線はこの破線で切れる
- **読む順番を1本にする。** 上段（見出し＋本文1・2）→ 核の一文（全幅・32px）→ 図（工程 → Before → After）→ 本文3 ＋ 着地3項目 → 最後の一行。
  左に見出し・右に図という構図はない。図は幅いっぱい（x=100.8〜1339.2）
- **赤の使い方を「理由」に一本化。** h2 の「分けない」、核の一文の「なぜそうしたのか」、After の赤い線とそのラベル、着地3項目の■、最後の一行の「理由」。
  すべて同じ意味（＝渡らないもの／RE DESIGN が渡すもの）で赤を使っている

## 2本線の図でどう読ませるつもりか

1. **工程行（1組だけ）**: `01 ヒアリング → 02 情報設計 → 03 原稿・デザイン → 04 実装・公開`。20px、間に小さな矢じり。ここは Before/After 共通の座標軸
2. **Before（工程ごとに担当が分かれる場合）**:
   - 上の線「成果物 / 構成・原稿・データ」: 黒 4px の実線。始点に●、切れ目ごとに■（モノが渡る印）、終点に少し大きい■（できあがったもの）
   - 下の線「なぜそうしたのか」: 赤 4px。始点に●（ヒアリングで理由が決まる）。切れ目ごとに 36px 空いて途切れ、区間ごとに薄くなる。最後の区間はほとんど見えない
3. **After（RE DESIGNの制作体制）**: 白 62% の面で囲って主役にする
   - 上の線: Before と同一（ここが要）
   - 下の線: 赤 5px、始点●から終点●まで切れずに1本。ラベル「なぜそうしたのか」も赤
4. 図の直下、本文3「理由を持っている人が、最後までいるということです。」が After の赤い線の説明になり、右の着地3項目が「だから依頼者に起きること」になる
5. 最後の一行は 22px で主張の一部として置き、上に赤い短い線（56×5、After の線の残響）を添える。「分けないのは人手ではなく、理由です。」を 900 で強調、「理由」を赤

## 実装コスト: 低〜中

- CSS グリッド＋インライン SVG 2枚（`viewBox 0 0 964 112`、線と●■だけ）。画像素材なし
- 列の座標は CSS 変数 `--col-w:229 / --col-gap:16` と SVG の x（切れ目 237 / 482 / 727）を手で合わせている。列幅を変えるときは両方を直す
- 動きは v13 `index.html` と同じ IntersectionObserver（`.rv` → `.in`、`.fig` だけ `.on` も付与）。
  `.on` で 成果物の線が左から描かれ（1s）、Before の「なぜ」が区間ごとに順に現れて薄れ、After の赤い線が1本で引かれる（1.5s）。すべて一度きり。
  スクロール量に連動する変化は無い。**静止状態＝完成形**。`prefers-reduced-motion: reduce` では最初から完成形
- 級数: 工程名 20px、行ラベル 18px、補足「構成・原稿・データ」15px、Before/After タグ 15px、工程番号 15px、ブロック見出し 18px。図中に 15px 未満の文字は無い

## モバイルでの組み替え方針

- 上段: 見出しの下に本文1・2を縦に落とす（01 と同じ）。核の一文は 24px 前後で2行に折る
- 図: **工程を縦に立てる**。左に工程 4 つを縦積み（各 72px 程度）、その右に 2 本の線を **縦線** として通す
  （左の縦線＝成果物、右の縦線＝なぜそうしたのか）。切れ目の破線は横線になり、工程の境目を横切る。
  Before と After は縦に並べる（Before が上）。行ラベルは各縦線の上端に置く。
  SVG は `viewBox` を縦長（112×W）に差し替えるだけで、●■と区間の座標は x↔y を入れ替えて再利用できる
- 下段: 本文3 → 着地3項目 → 最後の一行を縦に。最後の一行は 18px

## 巨大英字 `Process` を「入れた」理由

- 01・02 と同じ位置（left 0 / top 138）に置き、上段の見出しの後ろだけに掛かる。図（y=728〜）には届かない
- 02（`split/02-a.html`）が左固定×右縦積みで、03 は全幅と構図が変わるので、巨大英字の入り方だけは揃えてページのリズムを保つ判断
- 外周リング（790 / stroke 131）は外した。全幅の 2 本線と縦の破線の後ろに弧が入ると、線の切れ目が読みにくくなる

## 02（`split/02-a.html`）との構図の重複について

- 02 は「1本の縦線（S字）を赤い線がスクロールで伸びる」。03-P7 は「横の直線 2 本、静止で完成」。
  線という語彙は共通だが、縦↔横、1本↔2本、スクロール連動↔一度きり、と要素をすべて逆にしてある
- 02 の赤い線＝顧客の歩み、03 の赤い線＝理由。意味も別

## P2 との違い（形が近いので明記）

- P2 は「上の帯＝Before（担当A〜Dで切れる）／下の帯＝After（設計責任者で1本）」＝ **帯の意味が体制**。
- P7 は Before/After それぞれに 2 本の線があり、**線の意味は成果物／理由**。比較の軸が「誰が」から「何が渡るか」に変わっている。
  帯（面）ではなく線にしたのは、「切れている／つながっている」以外の情報（担当名）を載せないため
