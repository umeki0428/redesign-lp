## A案「1本の縦線」（`02-a.html`）

### 狙い
`proposals/02-a.html`「一本の導線」の直系。顧客が 01→05 を進む1本の道を、縦積みにしてそのまま伸ばした。スクロールに合わせて赤い線（顧客の歩み）が道をなぞり、線が通過した地点が赤く点灯、最後にゴール「問い合わせ」に届く。**左カラムに現在地（01〜05 ＋ いまの段階名）が出る**ので、右を読み進めている位置が固定側にも映る。

### 02-a.html から引き継いだもの／変えたもの
- 引き継ぎ: S字の道（sand 16px の道床＋赤 3px の線）、node-bg の地点円、赤い核の終点「問い合わせ」、凡例、道床が描かれてから地点が立つ動き
- 変えた: 地点間隔 140 → **200px**（縦積みで各段階に全文を置く余白）。赤い線は「読み込み時に一気になぞる」から「**スクロール量に連動して伸びる**」へ（セクション先頭で01、末尾でゴール）。文字は 19/14/13 → 22/16/15px。左カラム下に現在地を追加。通過済みの段階は墨70%に落として「いまの段階」を立たせる
- 総高さ 1340px（fig 1240 ＋ 上余白 100）

### STRUCTURE.md §4 の条件
1. 各地点に赤字の「設計すること」＋原稿の全文を静止表示。赤い線＝RE DESIGNが設計した道、を顧客がなぞる構図で、主役が RE DESIGN の仕事になる
2. 縦に伸ばしたぶん全文を15pxで静止表示（ホバー不要）。1段階あたり 段階名＋赤字1行＋全文2〜3行
3. 地点座標はパスの制御点と1対1。段階の増減は 200px 刻みでパスを書き足すだけ

### 実装コスト: 低〜中
01の `.dsc__*` と同じ絶対座標＋SVG。スクロール連動はパスを一度サンプリングして y→長さ の表を作る 30行ほどのJS。Figma には静止状態（全点灯）で戻せる。

### モバイルでの組み替え
左カラムの sticky を解いて通常の縦積み（見出し → 右カラムの内容）。道は S字をやめて左端 x=24 の直線にし、地点の右に文章を流す。現在地インジケータは非表示（sticky が無いので意味を持たない）。

## B案「対の行」（`02-b.html`）

### 狙い
1段階＝1行の表。**行の左半分に「顧客の段階」、右半分に「RE DESIGNが設計すること」を矢印で対にして置き**、5行を罫線で仕切って縦に積む。「顧客がこう動く → だから RE DESIGN はこれを設計する」が、どの行でも必ずセットで目に入る。画面中央に来た行だけ地が sand になり、矢印と番号が赤く点く。最後は「→ ● 問い合わせ」で着地。

### 02-a.html から引き継いだもの／変えたもの
- 引き継ぎ: 赤字の要約＋原稿の全文の2段構成、凡例の記号（○ / ■）、終点「問い合わせ」（赤い円）
- 変えた: 道・地点円を廃し、**罫線と矢印**で構成（図ではなく表に近い）。外周リングは行の地の邪魔にならないよう sand 25% に薄めた。動きは行ごとのリビール＋矢印の線描画＋中央行の点灯のみで、スクロール連動の線は無い
- 総高さ 1099px（3案で最も低い）

### STRUCTURE.md §4 の条件
1. 列見出し「■ RE DESIGNが設計すること」（赤）を右半分の上に固定。矢印の向き（顧客 → RE DESIGN）で、段階を受けて RE DESIGN が動く、という読みになる
2. 右半分は赤字1行（16px）＋全文（15px）。行は 34/36px の余白で詰めていない
3. 行は DOM を1つ足すだけで増減できる（座標計算なし）。最も差し替えやすい

### 実装コスト: 低
CSS grid と罫線のみ。SVG は矢印1本（30×12）。中央行の点灯は `getBoundingClientRect` で中心に最も近い行を選ぶ 20行ほどのJS。Figma にはそのまま表として戻せる。

### モバイルでの組み替え
sticky を解く。各行を「顧客の段階（上）→ 矢印を下向きに → RE DESIGNが設計すること（下）」の縦2段に組み替える。罫線はそのまま。列見出しは各行の上段・下段の小さなラベルに変える。

## C案「1段階ずつ大きく」（`02-c.html`）

### 狙い
1段階が **画面の高さいっぱい（min-height:100vh）** を使い、5枚の面を縦に積む。5画面ぶんスクロールするあいだ左カラムは動かない。面の中は 段階番号（96px）→ 段階名（40px）→ 歩みの円 → RE DESIGNが設計すること（23px）と、すべて大きく読ませる。**段階が進むごとに「歩み」の円が 1→5 に増え**（未来の段階は小さな点）、左カラムの5本のメーターも1本ずつ赤く埋まる。画面中央の面だけ番号が赤・不透明になり、隣の面は 42% に落ちて「切り替わる」。5枚目の面の中で「問い合わせ」の赤い核に着地する。

### 02-a.html から引き継いだもの／変えたもの
- 引き継ぎ: node-bg の地点円（歩みの円として縮小）、赤い核の「問い合わせ」、○ / ■ の凡例、赤字＝RE DESIGNの仕事
- 変えた: 道は無い。RE DESIGN が設計することは、**赤字の要約を別に置かず、原稿の全文を23pxで大きく置いて、仕事にあたる語句だけを赤にした**（例:「検索・広告・SNSなど、顧客との<span style="color:#d93832">接点を設計する</span>。」）。文言は一字一句そのまま、赤は強調のみ。01の外周リングは「面が切り替わっても動かない舞台」としてそのまま
- 総高さ 4370px（874px画面で 100vh×5）。3案で最も長い

### STRUCTURE.md §4 の条件
1. 各面の下半分（赤い罫の下）が「RE DESIGNが設計すること」で、面の中で最も大きい文字。顧客の段階名より仕事の文が目立つ配分にした
2. 面の中の文字は 5行程度（番号／段階名／歩み／凡例／全文）。全文は静止表示
3. 面は DOM を1つ足すだけで増える。歩みの円の数と左メーターの本数は面の数に合わせて手で揃える

### 注意（確認事項）
- 5画面ぶんのスクロールは長い。読み飛ばしたい人には冗長に見える可能性がある。min-height を 70vh 程度に詰める、または面の切り替えをスナップ（`scroll-snap`）にする、の2方向で調整できる
- 全文の中の語句を赤にする方式は、どこを赤にするかの判断が原稿ごとに要る（今回は「設計する／つくる／伝える／整える」に係る動詞句）

### 実装コスト: 中
面自体は flex の縦積みで簡単だが、100vh の面と sticky の左カラムの組み合わせは、ブラウザUIの高さ変動（モバイルのアドレスバー）で `vh` がずれる点に注意が要る（`svh` / `dvh` の使い分け）。中央の面を選ぶJSは B と同じ 20行ほど。Figma には5枚の面を縦に並べた静止状態で戻せる。

### モバイルでの組み替え
sticky を解き、面は `min-height:auto`（内容ぶん＋上下 64px）に詰める。段階番号 96 → 64px、段階名 40 → 30px、全文 23 → 19px。左カラムのメーターは、面の上に小さく「01 / 05」として各面に置き直す（固定側が無いため）。

## 補足

- 3案とも 1440px 固定の座標系（左 790 / 右 570）。1440px 未満のレスポンシブは未対応（比較用）。上記「モバイルでの組み替え」は方針のみ
- 動きは `prefers-reduced-motion: no-preference` のときだけ。静止状態（reduce 設定／アニメーション終了後）で成立する。スクロール連動（A の線、B・C の中央判定）は reduce でも動くが、線の伸びはトランジション無しで即時になる
- sticky の親は `display:grid; align-items:start` の `.frame`。セクションに `overflow:hidden` を付けると sticky が効かなくなるため、横方向のはみ出しは `overflow-x:clip` で止めている
- `design/v13/index.html`・`docs/`・`proposals/` 直下・`_archive-figma-content/`・`split/03-*`・`split/NOTES-03.md` は触っていない
