# 03 Process — スプリット案 A / B / C（左固定 × 右縦積みスクロール）[2026-09-04]

対象: `split/03-a.html` / `split/03-b.html` / `split/03-c.html`（各1440px幅・単体で開ける・高さは自由）。
スクショ: `split/shot-03-{a,b,c}-{1,2,3}.png`（1440×874、Playwright / Chromium。1=上部 / 2=中間 / 3=下部。
セクションの前後に 400px の黒いダミー領域を置き、段階スクロールでリビール発火後に撮影）。

前提: 発注者評価「`proposals/03-a.html` はおもしろい、B・C は微妙」＋新指示
「右カラムは縦積み。長くなるなら左カラムを固定し右カラムをスクロールするスプリットに」。
全幅レイアウト（旧B）と同心円（旧C）は使っていない。3案とも Before / After を両方表示している。

## 3案共通

- **左カラム**は `position:sticky; top:0; height:100vh` の固定層。番号 `03`・小見出し・h2・リード3段落の座標と級数は
  `design/v13/index.html` の `#s3`（01 Discovery）と同一（left 100.8 / top 117 / 幅 618.7、リード幅 553）。
  巨大英字 `Process`（Zen Kaku Gothic New 900 / 216px / -8.64px / 黒7%）と外周リング（790 / stroke 131 / sand 40%）も
  この固定層に入れてあるので、スクロール中も 01 と同じ画面構成が保たれる。リングは画面の縦中央（`top:calc(50vh - 395px)`）に留まり、
  スクロールする右カラムの後ろで「スポットライト」として働く
- **右カラム**は x=760〜1340（幅580、旧 `03-a.html` と同じ位置）。ここだけがスクロールする
- 固定層とスクロール層は同じグリッドセルに重ねている（`grid-area:1/1`）。セクションの高さ＝右カラムの高さ。
  `section{overflow:clip}` は 01 と同じだが、`hidden` にすると sticky が効かなくなるので注意
- 原稿は一字も変えていない。h2 の「分けない」だけをアクセント赤（01 の「事業を整理」と同じ扱い）
- `Before｜…` / `After｜…` の「｜」は Manrope のピル（Before=黒 / After=赤）＋太字テキストで表現。文字の「｜」は置いていない
- 級数: 担当ピル 16px、工程名 16px（円 118px）、Before キャプション 14px、After キャプション 16px Bold + 14px、補足 13px
- 図はすべてインラインSVG＋CSS。線描画（`stroke-dasharray`）→ ノードが立つ順序は 01 と同じ手法
- 動きは `prefers-reduced-motion: reduce` で無効化（B案のスクロール連動はアニメーションではないので残る）

## A案「上下で比べる」

- **狙い**: 旧 `03-a.html` の直系。右カラムの上に Before、下に After。工程4つを縦に並べ、
  Before は担当が4回替わる＝**4本に切れた縦線**（切れ目に「伝達」の点線矢印）、After は**1本の赤い縦線**が4工程を貫く。
  スクロールして After が画面に入った瞬間（ビューポート下 25% を除いた範囲に入ったとき）に赤い線が上から下へ 1.6s で描かれ「つながる」
- **旧A から引き継いだもの**: レーン2本の縦積み・ピル（白／赤）・node-bg の円（118px）・sand 線 7px と赤 5px・接点の白抜きドット・
  伝達の点線矢印・キャプションの級数・外周リング・リビール順（線 → ノード → ドット）
- **旧A から変えたもの**: 図を横流れ（担当が上・工程が下）から**縦流れ**（担当のレールが左・工程が右、行ピッチ 150）に。
  これにより Before の切れ目は「上下の切れ目」＝スクロール方向と一致し、After の1本の線もスクロール方向と一致する。
  左カラムを sticky に。ダミー領域を前後に置いた
- **セクションの総高さ**: **1,714px**（右カラム: padding 104 + Before 682 + gap 64 + After 708 + 補足 + padding 96）
- **実装コスト: 低**。旧A のレーン構造をそのまま縦にしただけ。追加は sticky の固定層のみ（JS は旧A と同じ IntersectionObserver）
- **モバイル**: 固定層を解いて通常の縦積み（見出し → Before → After）。図は 580×580 の座標系を 01 と同じ「等倍縮小」で持ち込める。
  行ピッチ 150 の縦流れなので、横幅 360px でも 0.6 倍で成立する（横長図にしない §20 の要件と相性がよい）

## B案「同じ図が変わる」

- **狙い**: Before と After を別々に描かず、**図を1つだけ置き、スクロールで Before → After に変化させる**
  （`docs/DESIGN.md` §21「同じ図が状態を変えて再登場する」の適用）。
  図はスクロール区間（`--scroll-len: 900px`）の中で sticky に留まり、その横を Before の文（区間の先頭）→ After の文（区間の末尾）が流れる。
  進行度 p（0〜1、両端 20% は静止）を JS が `--p` に書き、CSS の `calc()` で
  ①担当B・C・D の帯が上に集まりながら消え、担当A が「設計責任者」の赤い帯に入れ替わる
  ②4本に切れていた担当のレールが下に伸びて1本につながり、色が sand → 赤に変わる（JS で補間して `--rail` に書く）
  ③工程どうしの縦線が上から伸びてつながる ④伝達の点線矢印が消え、接点のドットが灯る
- **旧A から引き継いだもの**: ピル・円・線の語彙、sand → 赤の意味づけ（赤＝設計責任者）、キャプションの級数
- **旧A から変えたもの**: Before/After の2枚を**1枚に統合**。比較を「並べて見る」から「変化を目撃する」に変えた。
  文は図の横（幅240）に置き、スクロールで入れ替わる。スクロール連動の JS（`scroll` → rAF → `--p`）を追加
- **スクショ**: `shot-03-b-1`＝Before（p=0）、`-2`＝中間（p≈0.5、帯が集まりレールが赤くなりかけ、After の文が入ってくる）、`-3`＝After（p=1）
- **セクションの総高さ**: **1,740px**（右カラム: padding 104 + 区間 1,480（図 580 + スクロール 900）+ 補足 + padding 96）。
  実際に「読む」高さは A案と同じくらいで、900px は変化を見せるためのスクロール量
- **実装コスト: 中**。sticky の入れ子（セクション内の固定層 + 右カラム内の図）と、スクロール進行度を CSS 変数に流す JS。
  `calc()` 内の `var(--p)` は主要ブラウザで動くが、色の補間だけは JS で行っている。Figma では「前」「後」の2状態を別フレームで持つことになる
- **モバイル**: 図の横に文を置くスペースがないので、**図を画面上部に sticky、文を下に流す**縦構成に組み替える
  （図 320×580 は 0.9 倍で幅 360 に収まる）。または A案と同じく Before/After の2枚に分けて静的に置く（変化演出を捨てる）

## C案「工程を縦の軸にする」

- **狙い**: 4工程（ヒアリング／情報設計／原稿・デザイン／実装・公開）を**縦の軸として1組だけ**置き、
  左に Before の担当列（担当A〜D、切れた線と伝達の点線）、右に After の担当列（設計責任者、1本の赤い線）を並べる。
  工程は共通なので1回しか書かない。縦にスクロールしながら、**各工程の行で左右を見比べる**（同じ行で「誰が担当しているか」だけが違う）
- **旧A から引き継いだもの**: ピル・円・線の語彙、Before=切れた sand 線＋点線矢印 / After=1本の赤い線＋ドット、キャプションの級数、リビール順
- **旧A から変えたもの**: Before/After を上下ではなく**左右**に置き、工程を中央の軸で共有した（4工程 × 2 = 8 個の円が 4 個になる）。
  見出し（Before / After）とキャプションも軸の両側に分けて置いた。読む順序のため工程に Manrope の通し番号 1〜4 を添えた（原稿ではなく装飾）。
  行ピッチは 210 と広めにして、1行ずつスクロールで追える間隔にした
- **セクションの総高さ**: **1,232px**（右カラム: padding 104 + 見出し 88 + 図 760 + キャプション 16+~100 + 補足 + padding 96）。3案で最も短い
- **実装コスト: 低**。A案と同じ IntersectionObserver ＋ SVG の line。座標系は 580×760 の1枚
- **モバイル**: 左右3列（250 / 80 / 250）は幅 360 に入らない。**左の Before 列と右の After 列を軸の左右に細く畳む**
  （ピルを 14px・軸の円を 96px に落とし 0.62 倍で収める）か、A案の縦積み（Before 図 → After 図）に戻す。
  3案の中ではモバイル移植の手間が最も大きい

## 3案の比較（判断材料）

| | 右カラムの構造 | Before/After の見せ方 | 総高さ | 実装 | モバイル |
|---|---|---|---|---|---|
| A | Before（上）→ After（下） | 2枚を上下で比べる。After に入ると線がつながる | 1,714 | 低 | 容易（縦積みのまま縮小） |
| B | 図1枚が sticky、文が横を流れる | 同じ図がスクロールで Before → After に変化 | 1,740 | 中 | 要組み替え（図を上に固定） |

- C案は情報量が最も少なく（円が4つ）読みやすいが、左右比較なので「縦積み」の指示からはやや外れる。縦の軸を共有する案として添えた
